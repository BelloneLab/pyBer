# pyBer 0.57.2

Display fixes found by the new packaged-app audit, and automatic releases.

## Downloads

- **Windows GUI:** `pyBer-windows.exe`, with its runtime bundled inside.
- **Windows CLI:** `pyBer-cli-windows.exe`; `--version` reports `pyBer 0.57.2`.
- **Checksums:** `SHA256SUMS.txt` contains SHA-256 hashes for both executables.

## Fixed

- **Fields cut off in postprocessing drawers.** Opening a wide drawer (for
  example Setup) left the next drawer with a stale, wider page. In PSTH,
  Events and Spatial the right-hand fields were then drawn outside the drawer,
  so values were hidden. This was most visible at 100% Windows display scaling.
  Each drawer is now fitted to the visible width when it opens.
- **Paired fields spilling over the card edge.** Pre/Post and Start/End rows
  now declare the width they need, so the form wraps or widens instead of
  clipping the second field.
- **Small windows (laptops, 1024 px wide).** The Artifacts and Filtering
  drawers clipped their threshold fields because the manual-artifact buttons
  sat in one long row and form rows never wrapped. The buttons now use two
  columns and labels move above their field when a drawer is narrow.

## Release checks

- Every build now runs the packaged `pyBer.exe` in audit mode
  (`PYBER_UI_AUDIT`). It opens every preprocessing and postprocessing drawer
  and subsection at a desktop size (1500x950) and a small-laptop size
  (1024x700) and fails the build when any numeric value is hidden or
  clipped. The first run of this gate on GitHub caught the small-window bug
  above before it shipped. Screenshots and a JSON report are attached to every run.
- Releases are published automatically when `pyBer/version.py` changes and
  release notes exist. See [Releasing pyBer](../releasing.md).

## Compatibility

No analysis formula changed. Settings, projects and exports from 0.57.x load
unchanged.
